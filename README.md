## 📚 Исследуемые концепции и структура проекта

Проект разбит на три изолированных модуля, каждый из которых наглядно моделирует и решает конкретную архитектурную или алгоритмическую задачу многопоточного программирования:

```text
src/main/java/evg/megatron/
├── deadlock/   # Моделирование классической взаимной блокировки (Deadlock)
├── livelock/   # Моделирование активной блокировки (Livelock)
└── pingpong/   # Строгая последовательная синхронизация потоков (Ping-Pong)
```

## 🔍 Детальный разбор модулей

### 🔒 1. Deadlock (Взаимная блокировка ресурсов)
**Пакет:** `evg.megatron.deadlock`
- **Суть проблемы:** Имитация банковской системы (`BankService`, `BankAccount`), где два потока одновременно пытаются перевести средства между двумя счетами в противоположных направлениях.
- **Техническая реализация:** Демонстрация опасности вложенных блоков `synchronized (from) { synchronized (to) { ... } }` без глобальной упорядоченности захвата мониторов. 
- **Результат:** Искусственная задержка (`Thread.sleep`) гарантирует возникновение состояния Deadlock, блокируя выполнение потоков. Пример служит базой для изучения паттернов безопасного захвата локов (Lock Ordering / `ReentrantLock.tryLock`).

### 🔄 2. Livelock (Активная блокировка / Зацикленность вежливости)
**Пакет:** `evg.megatron.livelock`
- **Суть проблемы:** Моделирование ситуации «вежливых уступаний», когда два потока постоянно меняют свое состояние в ответ на действия друг друга, не выполняя полезной работы.
- **Техническая реализация:** Жизненная абстракция `TiredManAfterWorkAtBus` (Джек Воробей и Барбаросса уступают друг другу место в автобусе). Использование переменной `volatile boolean isWantToSitDown` и циклической проверки состояния параллельного потока.
- **Результат:** Потоки не заблокированы на уровне ОС (как в Deadlock), но процессорное время тратится на бесконечный цикл взаимных уступок.

### 🏓 3. Ping-Pong (Межпоточное взаимодействие)
**Пакет:** `evg.megatron.pingpong`
- **Суть задачи:** Организация строго поочередной работы двух независимых потоков, выводящих в консоль цифры "1" и "2" без состояния гонки (Race Condition).
- **Техническая реализация:** Использование классических механизмов монитора объекта (`lock.wait()` и `lock.notify()`) в связке с потокобезопасным флагом `AtomicBoolean` для контроля очереди выполнения.
- **Результат:** Идеально синхронизированный, бесконечный попеременный вывод данных двумя потоками с минимальными накладными расходами.

## 🛠️ Используемые технологии и инструменты
- **Java Memory Model (JMM):** `volatile`, видимость переменных между потоками.
- **Синхронизация:** ключевое слово `synchronized`, мониторы объектов, захват мьютексов.
- **Примитивы координации:** `wait()`, `notify()`, `AtomicBoolean`, `Thread.sleep()`.
- **Инструменты анализа:** Thread Dump, JVisualVM / JConsole (для визуализации блокировок).

## 🚀 Требования и инструкция по запуску

### 📋 Требования (Requirements)
- **Java Development Kit (JDK):** 25 версия
- **Сборщик проектов:** Apache Maven 3.8+
- **Операционная система:** Windows / Linux / macOS

### 🛠️ Инструкция по сборке и запуску (How to Run)

1. **Клонирование репозитория:**
   ```bash
   git clone https://github.com/shadjkez0r/week4_homework.git
   cd week4_homework
   ```

2. **Сборка проекта через Maven:**
   ```bash
   mvn clean package
   ```

3. **Запуск конкретных демонстрационных сценариев:**

   * 🔴 **Запуск симуляции Deadlock (Банковские переводы):**
     ```bash
     java -cp target/week4_homework-1.0-SNAPSHOT.jar evg.megatron.deadlock.Main
     ```
   * 🟠 **Запуск симуляции Livelock (Пираты в автобусе):**
     ```bash
     java -cp target/week4_homework-1.0-SNAPSHOT.jar evg.megatron.livelock.Main
     ```
   * 🟢 **Запуск симуляции Ping-Pong (Синхронизация мониторов):**
     ```bash
     java -cp target/week4_homework-1.0-SNAPSHOT.jar evg.megatron.pingpong.Main
     ```
